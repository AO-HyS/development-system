# Keep the implementation moving

## Start from a usable execution context

Resolve the authorized outcome, ticket dependencies and final review surface
once. Verify the canonical starting revision and the affected product entry point.
For authenticated UI work, confirm the needed role, organization and useful sample
state before the main verification pass. Login success alone proves no product
access. Keep a private pointer to the working credential source, not secret values.
Check that required browser/preview capabilities actually exist. Continue
independent implementation while a real access or host limitation is resolved;
keep the missing capability visible rather than treating it as a product defect.

Use the existing task record for only current scope, candidate/root, ownership,
accepted decisions, completed checks, unresolved findings and next actions.
On interruption, verify the live candidate and worker state, then resume pending
work. Retain usable output and test evidence whose candidate/input is unchanged.
Archive superseded status when rejection or new findings invalidate completion;
the current report and task state must agree about what remains unaccepted.

## Assign the work that shortens delivery

Use ready dependencies and disjoint ownership to choose concurrent work. One
writer may complete several adjacent tickets. Delegate a specialist only for
needed independent judgment or an actual bottleneck, with the smallest relevant
packet. A worker that has not started is a dispatch problem, distinct from slow
productive work. Confirm cancellation or termination before assigning replacement
write ownership; retain the failure and useful output instead of rediscovering it.

When sustained browser work dominates the parent, give one bounded pass to an
installed browser-QA role with the required browser/session capability if that
host supports the handoff. Keep simple interactions direct. Transfer current origin, session,
observations, authorized flow and stop conditions, without the full conversation.
One driver owns that session until returning results. The parent integrates the
compact receipt and retains product acceptance; visual critique stays independent
and must remain in the selected lane family. If that family lacks browser
capability, report the gap rather than silently substituting another family.
If browser handoff is unavailable, compose stable host operations directly.

## Correct the cause and finish the requested result

Use one current observation to prepare a stable browser segment and let tools run
it. After a failure, identify what prerequisite or tool state must change before
retrying. Repeating the same failed operation without new evidence is not recovery.
Use the repository's allowed alternative or a bounded diagnosis; preserve partial
evidence and report an unavailable capability. Do not add a browser bridge to
avoid the existing host boundary. `evidence-capture` owns capture mechanics.

Run focused checks during implementation. At integration, record which relevant
change, failure or required repo gate justifies each broader rerun. A real change
can invalidate prior checks; unchanged evidence should remain usable. Schedule
the required final checks after known code and visual corrections stabilize.

Before finishing, reconcile every requested outcome with the actual candidate,
reviewed behavior and accessible delivery surface. A worker's completion, clean
diff or local passing check does not discharge pending integration, QA or a
requested preview link. Continue authorized pending work; if blocked, name the
specific dependency and completed portion. Keep source, local runtime, preview,
production and acceptance claims separate. A timeout or unavailable receipt
cannot create a passing result.
