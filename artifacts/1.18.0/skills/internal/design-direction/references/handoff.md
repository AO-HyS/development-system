# Handoff that survives a new thread

Update the existing spec and tickets. Keep the current selected composition at
the top, with superseded explorations clearly separated. Preserve the authorized
scope and settled decisions; an implementation handoff does not reopen the grill.

Carry the approved image files through committed repository assets or durable
tracker uploads. When authorized, reuse correct existing attachments, upload
only missing selected files, and embed previews with descriptive links in the
spec and relevant tickets. Record each image's purpose, current status and
retrievable source or attachment ID. Temporary local paths, chat-only images and
expiring signed URLs are insufficient as the only handoff. Refresh an attachment's
download URL through its provider when required; authentication failure alone
does not prove the asset is absent. Open the selected file and verify its version.

Write a few visible acceptance criteria for each screen: primary task, hierarchy,
density, grouping, content area and responsive adaptation. Distinguish these from
functional invariants and scanner checks. Approved compositions govern those
choices. Illustrative copy, avatars, dates, clinical data and raster measurements
may be replaced with product truth; that exception does not erase the composition.
Explicit later user corrections govern the affected property only.

Give the next worker the current brief, exact relevant assets and owned criteria,
without historical chat. Verify from that packet that a fresh reader can retrieve
and inspect the selected images and explain which choices must survive. A tracker
link without viewable references does not complete a visual handoff.
