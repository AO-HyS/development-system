# Assets and motion

Use photography, illustration or generated raster artwork when the approved
concept calls for those materials. Native image tools are the first choice.
Check transparent edges against light and dark backgrounds. A CSS approximation
of a photographic asset is a fidelity gap, not an equivalent delivery.

Use generated video only when it serves an approved expressive concept and its
cost is authorized. Keep a static fallback and reduced-motion behavior. A video
asset used in the product is different from a real recording used as evidence;
one cannot stand in for the other. Never put provider keys into prompts, reports
or shipped code. Use the host's authorized credential mechanism.

Review usability, load cost and motion after adding assets. Decline ornamental
complexity that obscures the task. For operational UI, image generation and
animation are optional tools rather than mandatory stages.
