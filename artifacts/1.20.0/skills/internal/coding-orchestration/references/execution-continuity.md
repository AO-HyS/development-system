# Keep the implementation moving

Resolve the authorized outcome, dependency frontier and final review surface
once. Verify the canonical starting revision and affected entry point. For
authenticated UI work, resolve identity, role, organization and useful entities
before the main pass and retain only a private pointer to credential source.
Login success alone proves no usable product state.

Keep the task record to current scope, root and revision, ownership, settled
decisions, completed checks, findings, receipts and next actions. On
interruption, verify the live candidate and worker state before resuming.
Retain evidence whose candidate and inputs are unchanged; mark superseded
receipts when a correction invalidates them.

Use ready dependencies and disjoint ownership to choose parallel work. One
writer may complete adjacent files. Reassign a surface only after the previous
worker has terminated; preserve useful output and the exact failure. Completion
events are the synchronization boundary. Unchanged status is not new evidence.

After a failure, identify the prerequisite that must change before retrying.
Preserve partial evidence and report unavailable capability rather than treating
it as a product defect. Run final checks after code and visual corrections
settle, then reconcile every requested outcome with the actual candidate and
delivery surface.
