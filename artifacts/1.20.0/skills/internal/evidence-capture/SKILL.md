---
name: evidence-capture
description: Record an affected UI flow or package existing screenshots and video as deterministic delivery evidence.
---

The orchestrator retains product acceptance. A live browser or Computer Use
executor must have the actual host capability and receives a bounded neutral
plan. One driver owns each browser session. Deterministic host operations may
capture and package media without a model agent.

1. Bind the candidate, root, revision, authorized origin and path, viewport,
   fixture identity, role, organization and useful entities. Resolve that
   fixture once before the main pass. For a visual change, require completed
   Impeccable work and independent capable critique with findings resolved on
   this candidate. A missing receipt leaves visual acceptance unverified.
2. Select the affected walkthrough and distinct risk states. Give the neutral
   executor exact action inputs and the values to record; keep the acceptance
   rubric with the parent, who judges the resulting values. A portrait capture
   does not prove desktop composition. Reuse media only when candidate, data,
   environment and viewport still match.
3. Discover the authorized host's recording and interaction tools once. Read
   [host execution](references/host-execution.md), retain the existing
   execution-plan and authority checks, and do not add a browser bridge.
4. Start recording, perform the authorized actions, wait for the final visible
   outcome, and stop in a finally path. Serialize actions on one tab. Never
   replay a possibly committed write after an uncertain tool result; observe
   state first.
5. Verify that each original decodes, has nonzero duration and contains the
   actions and terminal outcome. Keep the originals and make one deterministic
   contact sheet with 4–6 representative frames per walkthrough. Use a crop or
   video segment only when it resolves a disputed detail or a motion claim;
   label every derivative with its source hash. Inspect the actual media end.

Capture existence, playback, functional success and visual quality as separate
claims. Return completed actions, tool failures, media references,
candidate/viewport/state and gaps. Keep credentials, raw frames and private
rubrics out of model output. The executor reports complete or incomplete; the
orchestrator decides product acceptance.
