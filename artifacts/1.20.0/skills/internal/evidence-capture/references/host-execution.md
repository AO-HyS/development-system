# Host execution

Code composition is an execution technique, not another authorization
protocol, model or browser. Use the existing host surface only when it exposes
the required tools. Tools visible to Codex are not automatically available to
a terminal script or another host. Stop at an unexpected origin or state.

Keep the repository's execution-plan format and authority checks. Enforce
redirect and click boundaries before effects. Keep opaque input references in
the authorized host and never put secrets in scripts or model output.

Use a read-only fixture to confirm tool composition before product writes. A
real recording proves the host operation only. A batch is one stable segment
with observable preconditions; metadata reads may run concurrently, but
actions and recording lifecycle on one tab serialize. Abort closes recording
and reports incomplete.

After a host failure, retry only after a relevant precondition changes.
Preserve failed diagnostic evidence and completed valid segments. A bounded
handoff includes root/revision, owned media paths, callable methods, authorized
action inputs, values to record, evidence shape and stop conditions; the parent
retains private acceptance criteria and judges the receipt. Request script
creation or correction once, then execute it without polling unchanged worker
status.

For existing media, use ffprobe for duration, codec and size and ffmpeg for
decoding or a deterministic 4–6 frame contact sheet. Preserve each original,
record its SHA-256 and name every derivative's source hash. Media inspection
does not certify behavior or design quality.
