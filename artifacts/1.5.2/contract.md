# Development System Contract 1.5.2

Version 1.5.2 retains every contract, authorization boundary, workflow, Reader, quality, observability, release, Check-in, Linear hygiene, Development Steward, and scheduler-runtime guarantee of 1.5.1. Published 1.5.0 and 1.5.1 bytes remain unchanged.

## Codex and T3 Code operational evidence patch

- Probe the installed skill catalog through ephemeral, read-only Codex only; T3 Code consumes that same Codex-compatible installation and does not own a second catalog mirror.
- Bind live evidence to the exact installed lock, Codex catalog version, source commit, executable, response contract, and installed folder hash.
- Do not read, require, recreate, or claim Factory catalogs, skills, executables, logs, or behavioral evidence in the current operational probe.
- Keep T3 Code application evidence separate from Codex skill evidence so a shared installation never impersonates actual client consumption.

## Codex and T3 Code guardrail patch

- Install, audit, and roll back the destructive-command hook only through the catalogued Codex engine; T3 Code inherits that hook.
- Never require, read, write, or restore Factory settings, skills, logs, or executables during a current guardrail operation.
- Preserve unrelated legacy Factory bytes exactly when they exist.
- Keep historical Factory benchmark and parity utilities outside the current documented certification path; immutable old artifacts remain available only as historical evidence.
