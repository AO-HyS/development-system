# The AF way (Claude Code)

The way of working measured on Barber (two tickets, Opus 5.5 High parent):
6.7 → 9.3 on the same measure. It is a recipe for the parent of a product ask
in Claude Code. Where it differs from the rest of `flow-implement`,
`coding-orchestration`, `behavioral-evidence` or `verificar`, this recipe
decides. The Codex host keeps its own path.

The parent manages: it decides, writes the «Terminado», the packets and the
verification commands, and integrates. Product code is written by
`escritor-rapido`; screens are proved by `verificador-pantalla`. While a child
runs, the parent moves other work of the same ask forward without polling.

0. **Cache.** In your second message, while the context is small, load in one
   call the only deferred tools you will use: `select:SendMessage`, plus the
   Linear tools for the close when the ask names a ticket. Then load nothing
   else. When an `Agent` or a background command says it will notify you, end
   the turn and let its notice wake you; follow any continuation a tool names.
   Read ranges (`sed -n`, `rg -n`) and short outputs (`head`, `tail`). If an
   essential capability needs another load, say so: do not pretend the measured
   recipe ran, and never drop a defence to keep the cache.
1. **First reply.** The parts of `in-your-own-words`, short. Whether you
   wait for his yes is decided by that skill's own rule; follow it as written.
2. **Writer now.** As soon as that rule lets you go on (right after the first
   reply, or right after his yes when it requires one), call
   `Agent(subagent_type="escritor-rapido", prompt=<packet>)` with no model
   override. The packet is a no-plan contract (no separate plan document): it
   carries exact owned paths, settled decisions, observable
   `acción -> lo que se ve` lines or mechanical target, and focused checks. The
   Claude orchestration guard admits a writer only with its
   typed packet, so write every field, one short line each, in the prompt:
   `Objective`, `Root` (this session's cwd), `Revision` (the 40-character
   SHA), `Owned paths`, `Settled decisions`, `Actions` (files, decision and
   the lines it must meet), `Authorization`, `Checks` (the lint and type
   commands it leaves green), `Stop conditions`, `Evidence receipt` and
   `Done when: <command> -> <observation>`. A denied dispatch names the
   missing field: add it and dispatch again, never drop the guard. The writer finds with `rg` every path that writes the
   affected state (create, change, delete, move, import, data already stored)
   before editing. Do not start `Explore`, `implementer` or another model's
   read inside the run.
3. **Parent in parallel.** Take the baseline (lint of the files, typecheck) and
   go over every entry point, error on load, error on save, retry, double click
   and a navigation failure kept apart from a save failure; what belongs to the
   ask becomes a line. Clarifications of the same scope go to the writer by
   `SendMessage`. Scope stays closed: you change only the behaviours the ask
   and the owner's rule name, plus the minimal integration and inventory
   changes the lints demand. A defect already there that breaks what the ask
   promises is part of the ask; another one in an operation the ask does not
   change is recorded as a finding, not fixed, and its line keeps its real
   result. Widening acceptance needs the owner's decision.
4. **Packet details, when they apply.** Ask the writer to edit only the
   blocks that change with `Edit` and to run lint and types once at the end.
   For a state machine the product's own architecture rules apply; the table
   helper lists, per state, the events it handles and the ones it ignores:
   `node ~/.codex/development-system/runtime/forma-af/tabla-maquina.mjs <machine.ts>`
   (it imports product code: run it only on modules the packet names; it does
   not prove guards, actions, wildcards or the screen). For a new dependency:
   `python3 ~/.codex/development-system/runtime/forma-af/lock-solo.py --antes <packages>`
   on a clean lock, then `pnpm --dir <app> add -E <package>@<version>`, then
   the helper without flags (a proposal, nothing written), review it, and
   `--write` (it runs `pnpm install --offline --frozen-lockfile` and restores
   its own generated bytes if that fails). The helper is a heuristic: a
   doubtful diff goes back to the writer with the lock left intact.
   Inventories and architecture lints are the product's own.
5. **Data before proof.** While the writer works, write a CLI script against
   the confirmed local or development backend (never production by default)
   that leaves the exact record each `pantalla` line needs, with a readback of
   its IDs and state. The verifier gets the data ready; it creates data on
   screen only when that is the very action being accepted.
6. **Verify once, fast.** When the writer is done and the product is ready,
   run the data script and, in the same message, launch
   `Agent(subagent_type="verificador-pantalla", prompt=<brief>)`, fresh and
   with no override, with the complete `verificar` brief (lines, seeded IDs,
   URL, account, login helpers, receipts folder); and run the `servidor` lines
   (three observations each) and the `regla` lines yourself. Keep their
   records apart when both mutate. One verifier, one round, five minutes; what
   it did not reach stays NO ALCANZADO. No visual council and no extra reader
   in the run; the integration read comes later, by level.
7. **Correct and close.** Open the receipts and captures `verificar` asks you
   to open. Each NO PASA goes back to the same writer by `SendMessage`, or gets
   «Rechazado: motivo» with its real verdict kept. After a fix recheck only that
   line and the lines it can touch, with a fresh verifier for the screen. A
   third NO PASA is diagnosed, told and left failed. Rerun the product's
   architecture checks against the baseline, then commit with its hooks (never
   `--no-verify`). Scale local concurrency flexibly without saturating the
   machine (no rigid thread cap), update the card and the Linear ticket, stop
   every server or watcher PID you started, close opened browser tabs/sessions,
   clean temporary artifacts and orphan MCP processes, and close in the page's
   format, saying there was no independent read inside the run.
