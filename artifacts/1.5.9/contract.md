# Development System Contract 1.5.9

Version 1.5.9 retains every guarantee and authorization boundary of 1.5.8. Published 1.5.0 through 1.5.8 bytes remain unchanged.

## Complete Working Backwards history

- Render every available canonical artifact as a full Technical Reader page and link the artifact rail to those Reader pages instead of raw Markdown.
- Keep Markdown canonical and expose its source link from each history page.
- State the visible position as `Fase X de 9` and explain that the active report is one phase of the wider initiative.
- For broad initiatives with named workstreams, carry a coverage ledger through later artifacts. Research answers residual questions and cannot silently replace the approved initiative scope.
- Preserve private-path containment, no-follow collision checks, mode `0600`, offline rendering, lifecycle gates, and authorization semantics for every generated history page.

## Bounded live review

- Start a tokenized localhost Reader after substantive Working Backwards checkpoints so the operator can review without manually opening a file.
- When the operator says they are away or on another computer, allow one tokenized, expiring Cloudflare quick tunnel scoped to the active private workspace.
- Serve only the current workspace HTML and Markdown plus the metadata-only Reader library. Deny traversal, symlinks, unrelated initiatives, directory listings, writes, analytics, indexing, and caching.
- Print local/remote URLs and expiry, keep the process controllable by the active harness, and stop on operator completion, abandonment, signal, or TTL.
- Live review grants no artifact approval, tracker write, implementation, commit, push, pull request, merge, release, deployment, paid-service, or destructive authority.

## Retained system guarantees

- Prompt-scoped architecture convergence is repository-wide: its Technical Grill carries the canonical architecture dimension matrix, evidence, decisions, and enforcement, and fails closed before approval when a required dimension is absent or empty.
- The complete product convergence covers repository and module maps, dependency direction, file placement, frontend and component design, backend and type contracts, testing, documentation, performance and security, observability, and migration sequencing. Component and module boundaries derive from cohesion and evidence, never arbitrary line counts.
- Agent guardrails, global anti-slop policy, and Release Train design remain Development System-owned capabilities. Product convergence verifies adapter compatibility but does not duplicate them as migration workstreams or tickets.
- Every architecture row marked change, remove, or unproven remains traceable through the later contracts and Implementation Map; focused provider research cannot silently narrow the initiative.
- Topic-based questions, natural-language approval, readable Mermaid, complete implementation reporting, named convergence workstreams, bounded measurable orchestration, and bounded attention quality remain unchanged from 1.5.8.
- Codex and T3 Code remain the only supported active harnesses. Published artifacts and manifests remain immutable.
