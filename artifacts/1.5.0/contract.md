# Development System Contract 1.5.0

Version 1.5.0 retains the lifecycle, authorization, benchmark, repository-preparation, delivery, measurement, privacy, installation, rollback, provider-readiness, Working Backwards gate, Reader, publication, and T3 handoff guarantees of 1.4.1. Published bytes remain unchanged.

## Definition routing

- Support Codex and T3 Code only. New generated contracts and adapters do not require Factory parity.
- Route a normal feature idea through `Product Grill With Docs -> Future Customer Story -> Technical Grill With Docs` before the established Working Backwards contracts.
- Keep the Product Grill non-technical and generate a compact customer story from its approved evidence.
- Derive Technical Grill Topics from the approved story, selected profile, repository evidence, unresolved Topics, and hard-risk triggers.
- Let Quick compact the same decisions, keep Standard as the complete default, and add risk-specific evidence for Complex.
- Allow an explicit simple-implementation path only with complete Quick evidence and no hard risk.
- Treat routing and generated documents as read-only recommendations. They grant no implementation, tracker publication, commit, push, PR, merge, release, or production authority.

## T3 workflow

- Persist Product Grill, customer story, and Technical Grill as distinct, hash-bound artifacts before research and the three formal definition gates.
- Never advance on negation, ambiguity, reported approval, or approval mixed with requested changes.
- Preserve exactly three formal definition gates for Product Contract, Technical Contract, and Implementation Map, followed by the private T3 handoff and a separate Implement Preview.

## Development-run measurement

- Record each real run with stable identity, objective, route, tickets, repository revision, harness, observed model, and monotonic events.
- Report discovery, definition, implementation, review, correction, checks, CI, provider time, agent wait, and human wait separately.
- Union overlapping intervals so concurrent work is never double-counted.
- Mark unavailable duration, tokens, cost, provider telemetry, and quality as `unproven`; never estimate them.
- Evaluate functional evidence against the five-minute target and require a recorded reason above ten minutes.
- Keep recording local and provider-neutral. Missing external telemetry never blocks delivery.

## Parallel Work

- Replace `work-multiple` with the public name and command `parallel-work`; retain the old spelling only as a deprecated migration alias.
- Compute the executable frontier from native ticket dependencies and group shared surfaces into sequential lanes.
- Permit concurrent writers only across disjoint lanes and keep exactly one writer per owned surface.
- Let a local failure block its lane and descendants while independent lanes continue when the shared base remains healthy.
- Default to one integrated branch and pull request. Separate pull requests require an explicit reason.
- Detect integration drift and conflicts before claiming one coherent candidate.

## Release Train v2

- Select checks, builds, data operations, provider deploys, and smokes from affected surfaces instead of a universal job list.
- Deduplicate identical evidence across workflow and deploy scripts.
- Reuse exact revision-bound build artifacts when a provider permits it and record forced rebuilds otherwise.
- Measure changed validation, integrated certification, preview, data operations, promotion, and production smoke separately.
- Keep migrations and backfills behind dry-run, ordering, rollback, and risk-specific authorization.
- Contain missing credentials to the affected provider lane while healthy lanes continue.
- Never translate Git success into preview or production without exact provider, destination, smoke, and rollback evidence.

## Stack quality profiles

- Select architecture and quality evidence from declared, changed capabilities instead of running every oracle on every change.
- Keep rule ownership non-overlapping across lint, typecheck, focused tests, React Doctor, Impeccable, Codex Security, Convex review, stack profiles, and provider checks.
- Treat owned TypeScript type erasure as a finding and allow only narrow, documented external-boundary adapters.
- Default new cross-platform mobile work to Expo/React Native while preserving deliberate iOS, Android, and Electron profiles.

## Check-in and Linear hygiene

- Route natural phrases such as “Ya llegué” or “Estoy en el celular” to a short, read-only Check-in report.
- Reconcile repository, tracker, pull request, CI, preview, release, observability, and development-run evidence without letting one source impersonate another.
- Classify human actions by mobile, computer, local-device, or promotion-authorization capability and preserve separate authorization for every write or promotion.
- Keep explicit product mappings for AO HyS, Casa Roca, The Barber Central, NutriPlan, and ETERIA. Preview complete Linear cleanup before any separately authorized external mutation.

## Development Steward

- Run a weekly, headless, read-only review only for the five explicitly allowlisted primary repositories.
- On macOS, provide a reversible `launchd` schedule for Monday at 09:00 local time. Install managed runner, prompt, state, logs, and reports under private HOME with restrictive permissions; execute Codex ephemerally in a read-only sandbox and without a shell.
- Audit the loaded service and exact managed hashes. Fail closed on unmanaged files, symbolic-link parents, or drift; disabling the scheduler must preserve completed reports.
- Evaluate upstream changes using pinned current and candidate versions, diffs, changelogs, and local evidence. Never adopt `latest` or use stars as the sole signal.
- Keep a repository collection failure local, produce one concise private report for Check-in, and expose missing evidence as unproven.
- Safe deterministic updates may prepare a branch and draft pull request after focused checks, but never auto-merge, release, or promote production.

## Convex and observability

- Audit Convex authorization, validators, public exposure, indexes, pagination, bounded reads, subscriptions, contention, actions, scheduling, migrations, official components, and storage boundaries without live mutation.
- Keep domain records and relationships in Convex while evaluating Cloudflare for suitable binary and static storage.
- Treat PostHog as the target observability surface only after production-only instrumentation, privacy, release identity, source maps, exceptions, conversion signals, replay, and Web Vitals are proven per repository.
- Low traffic or a small Web Vitals sample is an investigation, not proof of broken instrumentation. Only an explicit failing probe can establish that failure.
- Prepare a bounded draft fix only after deterministic reproduction at an exact revision, a bounded root cause, and a passing regression test. Never remove a legacy provider automatically.
