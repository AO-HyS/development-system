# ADR 0070: Haiku 5.5 for bounded roles

Status: accepted by operator instruction on 2026-10-07. Contract 2.1.2.
Supersedes ADR 0060 D14's blanket Haiku prohibition for the roles below.

## Decision

Select the exact model `claude-haiku-5-5`, Medium effort, for bounded source
facts/research and exact/mechanical execution. This is the operator's selection;
no comparative benchmark or evaluation is required or claimed. Real behavior
verification remains mandatory. The complete tuple can be reverted if delivery
becomes slower; there is no automatic model or provider fallback.

Claude Explore, code-mapper and docs-researcher remain read-only. Only protected
mechanical-worker and exact-implementer may write, with complete packets,
exclusive ownership and writer Git hooks. Sonnet retains general implementation;
Sol 6.1 High plans and independently reviews; Opus retains UI/visual roles.
Aliases, other Haiku versions, plugins and unregistered writers remain denied.

Codex native Sol/Luna profiles remain explicit same-provider alternatives for
restricted Codex work. Claude IDs are never put into Codex model profiles. T3
Haiku readers are available through the live catalog; T3 source writers remain
unadmitted. When no protected native Claude writer route is observed, the
authorized parent edits directly and preserves the verification gap.

## Distribution and evidence

Version roster, policy, guard, templates, instructions and affected skill bytes
in new immutable snapshots. Update the complete global tuple once per computer;
product builds/deployments are not needed. Existing threads retain their context.
Observe model identity and actual native hooks separately from installation.
An installed profile or a direct Node hook probe does not prove a live host
loaded it. No public package release or product deployment is implied.
