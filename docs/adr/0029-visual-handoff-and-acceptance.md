# ADR 0029: Transfer approved composition and verify the delivered outcome

Status: accepted; operator authorized correction and production publication on
September 10, 2026. NutriPlan reimplementation belongs to a subsequent thread.

The Continuum pilot passed mechanical checks but the operator rejected visual
fidelity. The writer and critic had opened approved references. Correct responsive
boards were already uploaded to the tickets; the Linear spec exposed local paths
without embedded images. An earlier diagnosis incorrectly implied all uploads
were missing. Inspection of attachment bytes corrected that claim. This is both a
handoff discoverability issue and an acceptance failure, not evidence that a model
or Impeccable installation alone caused the result.

The critic treated hierarchy and density deviations as optional improvements,
then closed a bounded geometry list. The parent treated that closure as full
acceptance. The final fixed-duration recording ended before the final interaction;
decoding and sampling earlier frames did not establish a complete walkthrough.

Release 1.16.0 / catalog 0.37.0 updates existing design-direction, grill-with-docs,
design-quality, evidence-capture, coding-orchestration and implement-spec skills,
plus the existing visual reviewer profile. It adds no coordinator or universal
gate. Use Matt Pocock writing-for-agents and Codex skill-creator principles:
concise rules, one detailed handoff reference and realistic forward verification.

- Put viewable selected assets and composition criteria in the existing spec and
  tickets. Inspect current attachments before reuploading or diagnosing absence.
- Compare a representative screen early when establishing shared visual language.
  Keep this internal; retained approval does not need another user ceremony.
- Treat material departure from approved composition as a visual blocker. Separate
  a bounded review's scope from acceptance of the complete requested outcome.
- Match capture state and viewport to the claim, include the final visible outcome
  in the clip and inspect the actual file end. Stable actions use native batches.
- Resolve authorized scope from a named spec without requiring the user to recite
  ticket IDs. Use a task frontier and isolated worktrees when they solve actual
  dependencies or ownership, not for every bounded ticket.
- Preserve required repo gates; choose focused checks during editing and rerun
  only after relevant changes, failures or unresolved concerns. Rejected delivery
  remains an incomplete attempt when reporting elapsed time.

The product tickets and spec are corrected separately in their private tracker.
No product data, images, transcripts or private reports ship in this package.
Existing model defaults and provider order remain; this failure does not establish
a comparative model ranking. Published older artifacts are immutable.

Verification includes canonical hashes, required repository checks and isolated
installation, drift, failed validation, reinstall, rollback and unrelated-file
preservation. A fresh-context visual/evidence exercise checks the changed decision
rules. These observations establish the tested behavior only; they do not guarantee
one-pass feature delivery, visual acceptance or faster future runs.
