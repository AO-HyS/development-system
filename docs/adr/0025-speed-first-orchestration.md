# ADR 0025: Rápido → bien → barato

Status: accepted for local implementation, operator instruction 2026-09-09.

Optimize elapsed time to the requested usable functionality, including corrections
and delivery. Correctness is second, cost third. Preserve authorization and data
boundaries. The own orchestrator remains: Astra decides and integrates; capable
fast workers execute. Provider order is informed by comparable runs;
its actual relative speed is not established by its labels.

Resolve providers in the parent once. Remove recursive routing instructions from
five selected Luna workers. Use bounded context and native lifecycle primitives.
Concurrent work needs independent ownership and must shorten the critical path.
Research or prototype where uncertainty makes it likely to avoid slower rework.

New tests are optional and justified by a concrete failure they help correct.
Use the quickest adequate check; preserve required existing repository gates.
This change does not delete test suites or claim lint/design scanners prove runtime
behavior. Ordinary completion uses the final response; separate documents serve
requested or durable evidence needs. Visual acceptance retains independent Astra
critique after Impeccable and before final delivery recordings.

Apply Matt Pocock writing-for-agents: one owner per decision, conditional pointers,
concise task packets. PStack Part 2 informs selective research and executable
prototypes, not mandatory candidate tournaments or another orchestrator.

Candidate 1.12.0 and catalog 0.33.0 preserve old immutable versions. Verify hashes
and isolated installation/rollback plus required repository checks. Installation
is not evidence of live influence or a speed benchmark. Four controlled Low/Medium
runs remain pending user-created Linear tasks.

## Bounded worker observation

A September 9 synthetic availability function passed eight independent cases
on all four routes. OpenCode Go Muse High CLI: 27.704 s; native Luna Max:
80.791 s; native Luna Max with a focused packet: 52.210 s; Luna Max CLI with
priority requested: 34.112 s. One sample per configuration, differing harnesses
and concurrent runs prevent a general model ranking. Native logs confirmed Max
but did not expose service tier. Keep measured rankings provisional.

The first native worker reloaded global lifecycle skills and inherited the parent
cwd despite an isolated task. Clarify in worker instructions that the parent has
already routed lifecycle/provider and the supplied task root governs execution.

Fix the resolver ignoring serviceTier and always emitting priority. Verify direct
roster changes to default and priority affect the generated CLI arguments. This
does not reconfigure running native agents or change the active user's config.

## Retire providers from active execution

The operator explicitly excludes Factory/Droid and Devin. Remove them from the
editable and released roster and replace Fable review routing with Astra. Update
current skills and generated repository guidance. Native Luna profiles use Max
and priority; the host must load the new profiles to apply these values. Keep
historical artifact versions and restoration support immutable. Compatibility
mirrors of design skills are not provider execution routes.

An eight-run mock matrix covers frontend adaptation, backend ranges, source
exploration and schema reading. Sources are pinned product snapshots; the two
implementation tasks are isolated reproductions, not product deployments.
Astra Medium independently accepted both rendered variants. Two prose findings
required correction: Luna reversed route-mask reload behavior; Go described an
optional numeric timestamp as nullable. Final report retains first attempts and
correction durations. This supports a Go-first bounded execution policy with
Luna Max/priority as alternative, not universal performance claims.
