# 0024: Review design before final evidence; compose stable host operations

Status: accepted for 1.11.0 by the operator's September 8 instruction.

## Problem

A private retrospective found repeated large-context browser/coordination turns
concentrated in Astra. Cached input dominated token totals; raw tokens are not
subscription charges. The sampled expensive tasks did not execute new Go work,
so cross-provider context loss is not established as their cause. Global and
project Impeccable copies also diverged; installation alone did not demonstrate
that agents loaded the current workflow or that designs passed visual review.

## Decision

Vendor the complete Impeccable 4.3.0 skill, its pinned launcher and the existing
16 command shortcuts in catalog 0.32.0. The main skill exposes all its commands
and references. Preserve upstream content and historical published artifacts.
Create narrow `design-quality` and `evidence-capture` skills using Matt Pocock's
writing-for-agents mechanics (progressive disclosure, concise triggers and
external references), not another universal lifecycle router.

The orchestrator sends working screenshots to an independent Astra visual
critic after Impeccable. Resolve concrete findings before recording the final
delivery evidence. An independent Impeccable finish reviewer can fill this role;
self-review cannot. Confirm affected states after corrections, without score
threshold loops. Working screenshots and functional probes remain available
before critique; only the final package is gated on reviewed visual completion.

Astra keeps live Computer Use and final judgment. Luna has a dedicated optional
route for bounded scripts and media preparation. Tools perform deterministic
recording/file work. Use one driver, native host composition, compact results
and representative flows plus distinct risk states unless exhaustive coverage
is requested. Reuse the existing execution-plan protocol. A proposed generic adapter helper
was tested privately but is not distributed: native host composition already
worked, and a second schema would duplicate the current authority boundary.
Do not install a second interpreter, broker or daemon to imitate composition
already provided by Codex/T3. Keep general implementation provider order intact
until comparable outcome evidence supports changing it.

## Verification and limits

Verify catalog hashes, routes, native read-only recording composition and isolated installation,
drift, failed validation, reinstall, rollback and unrelated-file preservation.
Measure real completed outcomes after rollout; no numeric savings or quality
improvement is claimed from configuration alone. Local project skill copies need
explicit migration because global installation cannot override their precedence.

## Reproducible current certification

The inherited suite had 24 stale assertions against earlier versions and
implicit delegation. Update fixtures to request structured review explicitly
and derive current versions from release metadata; retain mutation, authority
and exact provider availability assertions. The July 20 pilot audit additionally
requires three operator-private AOH-147 recap files that are absent after the
runtime-directory replacement. Keep `pnpm rollout:validate` available as an
explicit historical audit; remove it from current `verify`, which runs roster,
type, behavior and canonical-repository validation. The isolated `scenario`
checks installation and skills, drift, failed validation, reinstall, rollback,
lifecycle and repository preparation. Missing historical private files do not
certify or invalidate the current release; no recap is fabricated or marked
verified. This is a deliberate retirement of a historical pilot gate, not a
claim that its missing evidence was recovered.

The live upgrade exposed pre-existing Impeccable aliases in `.codex/skills`
and `.factory/skills`. Catalog 0.32.1 / contract 1.11.1 declares their exact
canonical mirror relationship instead of treating them as unmanifested
entries. The isolated skill scenario now starts with those upstream symlinks
and verifies identical mirrors after installation and restoration on rollback.
No published 1.11.0 artifact or 0.32.0 catalog is rewritten.
