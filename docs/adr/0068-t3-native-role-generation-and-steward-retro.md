# 0068 — T3 native delegation, generated roles and durable retro

Status: accepted by the operator on 2026-10-03. Contract: 1.41.0.

## Decision

Extend `config/agent-roster.json` as the existing single source for host roles.
`src/role-policy.mjs` generates Claude policy, agent instructions and host sections;
the release builder uses those profiles for all native Codex role artifacts.
Generation consistency and roster validation reject drift before publication.

Opus 5.5 owns UI design and independent visual critique. Named protected Sonnet
5.5 roles execute bounded packets. Sol 6.1 High plans, reviews backend/security
and performs computer use; Luna 6 High priority collects bounded facts.
Requested settings are distinct from observed runtime identity and capabilities.

Use app-owned T3 child delegation and preview tools directly. Cross-provider
read-only review and browser verification are admitted; source writing remains
on protected native host routes until equivalent enforcement is observed.
Keep the existing CLI account recovery and receipt-validated Claude fallback.
Jev remains explicit advice at meaningful decision boundaries, with automatic
tier/classification disabled; it does not grant authority or acceptance.

The Claude writer guard requires the full execution packet and executable
`Done when:` before ownership admission. Primary fresh Opus visual critique
does not require a Codex failure receipt; any supplied fallback envelope still
requires complete receipt validation. Unknown writers fail closed.

## Maintenance

Reuse Development Steward with a private atomic retro ledger. Collection cursor
and recommendation resolution are separate. Repository plus stable change ID
deduplicates PRs across revisions; failed publication remains retryable.
Draft admission requires an explicit clean revision and no active writer.
At most one useful independently reviewed PR per repository is proposed; no
automatic merge, release, deployment or product data effects are authorized by
the schedule. Development System is explicitly added to the existing allowlist.

Use one scheduler. T3 can replace the existing launchd collector after disabling
that collector without deleting its history. Future scheduled dispatch does not
prove its provider turn or first weekly result succeeded.

## Continuity and boundaries

Keep current work concise and retain historical continuity through immutable
Git history and a private exact archive. History discovery checks actual SQLite
schema; a V2 database may retain legacy project mapping tables.

NutriPlan's official Convex lint coverage is a separate develop-only handoff
preserving active feature writers. Existing Casa Roca coverage and Barber's
custom guard are retained. Pi, Effect adoption and automated test tooling are
outside this release. No automated tests or evals are introduced or executed.

Production acceptance requires focused repository gates, isolated-HOME
installation, independent review, real browser/hook evidence, published package
provenance and operator installation audit. File copying alone does not prove
host loading. Consumer tooling advances only when active ownership permits.
