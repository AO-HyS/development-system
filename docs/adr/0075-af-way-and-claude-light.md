# ADR 0075: the AF way in Claude Code and `claude-light apply|undo`

Status: accepted direction; candidate contract 4.1.0 / catalog 0.86.0.
Builds on ADR 0069 (one shared installation) and keeps ADR 0074 (one progress
format). The Codex host does not change.

On 2026-11-19 the owner approved the AF way after two Barber tickets, one run
each with an Opus 5.5 High parent in Claude Code, went from 6.7 with 4.0.0 to
9.3 on the same measure. The way and the light start were measured together;
nothing here promises that score, speed or saving for another product, task or
host. Before publishing, one new real ticket of NutriPlan or Planeta Aula,
launched by the owner, runs with the candidate package.

Decision:

- The global page keeps its 4.0.0 bytes (7,955 of 7,956). The AF steps live in
  the Claude-only rule `~/.claude/rules/orchestration.md`, rendered from
  `hostProfiles.instructions.claudeRule` of `config/agent-roster.json`, at most
  2,500 bytes. The 4.1.0 builder checks both sizes and refuses a page that
  differs from 4.0.0.
- The parent manages; `escritor-rapido` (Sonnet 5.5 medium; Read, Edit, Write,
  Bash, Grep, Glob; the writer Git hook) writes the product code from a packet
  of files, decision, lines and lint/type commands; one fresh
  `verificador-pantalla` (Sonnet 5.5 medium; Bash, Read, Write and five Browse
  tools; no product edits) proves the screen lines in one round of five
  minutes and signs in with the two `verificar` helpers. Each NO PASA goes back
  to the same writer by `SendMessage` or is answered «Rechazado: motivo».
- The full recipe is `flow-implement/references/forma-af.md`, read before the
  first Agent; `coding-orchestration`, `behavioral-evidence` and `verificar`
  open with a Claude AF branch and keep their earlier text for Codex.
  `in-your-own-words` does not change; the recipe points to its pause rule.
- Inside an AF run there is no other model read and no visual council. The
  integration read by level, `listo`, Codex answers, the smoke, the five stops
  and the close stay.
- Two helpers ship under `~/.codex/development-system/runtime/forma-af/`:
  `tabla-maquina.mjs` (events each XState state handles and ignores; it
  imports product code and proves no guard, action or screen) and
  `lock-solo.py` (keeps in `pnpm-lock.yaml` only the added packages: refuses a
  dirty lock or an empty list, proposal by default, `--write` explicit, puts
  back its own generated bytes when the frozen install fails). XState shape
  rules stay in Barber.
- `development-system claude-light apply|undo <repo>` merges only reduction
  keys into `<repo>/.claude/settings.local.json` from one of four versioned
  profiles (Barber, NutriPlan, Planeta Aula, Casa Roca) that travel inside the
  package. Apply keeps every other key and joins denials; undo restores the
  exact earlier bytes, or removes the file it created, and refuses when the
  owner edited it afterwards. HOME settings, `.claude/settings.json` and
  `.mcp.json` are not touched; the shared installer gains no product settings.

Rollback is two explicit steps: `claude-light undo` in each repository where
it was applied, then `development-system rollback`. Installed bytes do not
prove that Claude Code loaded the rule or the agents: that is observed in a
fresh T3 thread, first with the local candidate and, after the production
answer, with the installed package.
