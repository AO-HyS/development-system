# ADR 0047: Govern the complete feature with Jev and independent judgment

Status: user-authorized implementation and production rollout, 2026-09-21.
Supersedes ADR0046's advisory-only default and all-Astra research restriction.
Preserves its disabled historical controller and selected-parent ownership.

Definition and implementation can occur in different threads. Astra XHigh
creates a spec and separate linked tickets. A later selected parent, normally
Sol High, retrieves the whole approved contract and keeps every ticket in scope.
Fast researchers collect bounded facts. Astra authors the implementation plan;
a distinct fresh-context Astra reviews it before writers. Exact writing defaults
to Flash High. Substantive unresolved decisions may use an explicitly justified
Astra packet. There is no silent fallback or global two-writer cap.

Jev is present throughout intake, research, planning, independent plan review,
dispatch, returned changes, corrections, integration, deep review and closure.
It classifies explicit supplied obligations and route proposals. Sol/Astra
interpret findings and decide technical changes. Deterministic code owns
identity, freshness, one-shot permits, dependencies, ownership and closure.
Unknown, missing and unavailable evidence cannot grant a passing permission.
Action readiness and completed acceptance use different obligations.

A new governance runtime supplements the compatible advisory CLI. It uses
short atomic transactions, scoped filesystem fingerprints and observed host
events. No old experimental controller is reactivated. Plan/review/evidence
outputs carry actual producer and candidate provenance; arbitrary imported
success JSON cannot close a run. Unrelated parallel edits do not invalidate a
disjoint packet, while changed inputs invalidate affected evidence.

The runtime enforces ordinary supported agent operations, not security against
arbitrary code running as the operator. Synchronous Codex hooks require trust;
the host may skip unavailable, untrusted or terminated hooks. Native writable
children require proven identity. Hosted tools, opaque nested code and external
worker internal tools require separate capability evidence. External process
launch/lifetime/integration is distinct from internal tool governance.
Unsupported required capabilities must stay explicit and block that route.
User interruption is authoritative, and missing termination preserves ownership.

Specs and tickets keep stable criterion/dependency/rule/evidence links. Current
files, commands and candidate hashes belong to runtime packets. Backend features
receive the same acceptance chain; only visible outcomes require visual checks.

Release 1.25.0/catalog 0.45.0 preserves immutable prior versions and merges hooks
without deleting unrelated handlers. Validate in isolated HOME, then publish and
install the authorized candidate. Operational acceptance requires observed host
denial/approval and a real Jev path; copied files alone are installation evidence.
Record certified surfaces and remaining gaps with the delivered release.
