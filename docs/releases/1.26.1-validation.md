# 1.26.1 governance lock recovery validation

An orphaned HOME-wide registry lock could deny tools across unrelated sessions.
The previous implementation intentionally had no stale-owner recovery. A real
SIGKILL reproduction failed with `lock-timeout` before this correction and
succeeds with the permanent SQLite mutex and recoverable compatibility record.
The original incident owner's exit cause is unknown.

The independent plan and final source reviews passed. A discovered interpreter
mismatch was corrected: installed hooks execute the exact validated Node binary.
Published 1.26.0 artifacts and manifests remain unchanged.

Validation on 2026-09-21 (local date):

- `pnpm run verify`: 771 tests passed, types/roster/repository healthy.
- After the interpreter correction, affected lock and installation tests:
  24 passed, including all 19 lock/recovery regressions; typecheck passed again.
- `pnpm run scenario`: 28 scenario tests and all installation/skills/lifecycle/
  repository stages passed using isolated HOME.
- Updated `node scripts/reproduce-governance.mjs`: 1.26.1 installation,
  failed-upgrade restoration, unrelated hooks, drift, rejected validation,
  reinstall, actual installed-owner SIGKILL recovery, rollback, prior catalog,
  and unrelated-file preservation passed.
- Generated release check: 60 manifest artifacts and 13 runtime files match.
- Exact reviewed test-change policy and whitespace checks passed.

Regressions cover live/dead/unknown legacy ownership, permission uncertainty,
same-process initialization, independent concurrent recoverers, PID reuse,
mutex identity mismatch, replacement protection, interrupted archive and owner
publication, and actual hook ingress retaining run bytes, checksums and leases.
The original orphan bytes and completed recovery receipt are checked explicitly.

All crash injection used isolated directories. This is local filesystem,
same-host coordination. Ambiguous legacy identity and persistent storage errors
remain explicit failures. Lock recovery grants no attempt completion or product
acceptance, and synthetic host metadata does not establish provider identity.

Publication and activation are separate from these source/package checks.
