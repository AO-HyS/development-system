# 1.28.0 field-notebook reports and margin questions

Standalone reports now render as a field notebook that leads with one verdict,
a stamp line, optional signals and numbered findings with drawn status marks.
Sections and contents are numbered; a night palette persists per browser. Maps,
charts, Mermaid, PR Lens evidence, callouts and offline operation are retained.
Readers can ask a question beside any paragraph, keep drafts locally and send
them as one batch. Canonical workflow Readers keep their existing presentation.
See [ADR 0052](../adr/0052-field-notebook-report-and-margin-questions.md).

Focused local verification passed:

- 4 new notebook tests: verdict selection and fallback, status marks, numbering,
  `data-q` anchors, embedded fonts, CSP script-hash binding, managed
  regeneration, and the question endpoint. The endpoint test covers revisioned
  storage with mode 0600, receipts, 409 conflict, 403 cross-origin, 400 invalid
  batch, 415 non-JSON, 404 missing reader, 405 method and 404 symlinked storage.
- 22 existing reader-live, technical-reader, technical-report and
  visual-document tests against their published versions, with zero failures
  or skips (26 total).
- A browser run of the delivered renderer: two saved questions, batch send,
  revision 1, persistence after reload, and the keyboard-only flow.
- Rendered design gates: hero 86%, responsive 84%, motion and sections passed.
  An independent finish review found three issues; two were fixed (tray
  overlapping a finding mark, mobile topbar clipping a heading) and one was
  refuted from source (the theme icon is already SVG). The second review
  returned ship. The anti-pattern detector reported nothing.
- The release builder checks 60 manifest artifacts. Catalog 0.47.0 retains 104
  skills and 140 variants; only the copied working-backwards skill (27 files)
  changes. `git diff --check` and the closed test policy pass.

These results establish local rendering and server behavior in isolated
fixtures. They do not establish installed-host discovery or loading. Isolated
upgrade validation, publication and operational use remain separate checks.
All earlier manifests, catalogs and artifacts remain immutable.
